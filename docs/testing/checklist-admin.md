# Чек-лист: Адмін-панель

## Автентифікація
- [ ] Вхід по логіну/паролю працює
- [ ] Невірний пароль: показується повідомлення про помилку
- [ ] Сеанс не закінчується при оновленні сторінки (localStorage/cookies)
- [ ] Кнопка "Вийти" закінчує сеанс і перенаправляє на вхід
- [ ] При закритті браузера: сеанс зберігається (або пропадає за 24 години)

## Каталог (список спеціалістів)
- [ ] Завантажується повний список спеціалістів
- [ ] Показується кількість записів
- [ ] Таблиця має колони: ID, ім'я, категорія, локація, ціна, акції
- [ ] Сортування за колонками працює
- [ ] Пошук по імені працює в реальному часі
- [ ] Пагінація або infinite scroll

## Додавання спеціаліста
- [ ] Форма "Додати спеціаліста" відкривається
- [ ] Всі поля видимі: ім'я, категорія, локація, ціна, опис, соцмережі
- [ ] Обов'язкові поля помічені (*)
- [ ] Валідація:
  - [ ] Ім'я: не може бути пустим
  - [ ] Ціна: тільки цифри, > 0
  - [ ] Категорія: обов'язковий вибір зі списку
  - [ ] Локація: обов'язковий вибір зі списку
- [ ] Кнопка "Зберегти" лякає запит на сервер
- [ ] Успішне додавання: спеціаліст з'являється в списку
- [ ] Зберігання в базі: новий ID, timestamp

## Редагування спеціаліста
- [ ] Клік на картку/рядок: форма редагування відкривається
- [ ] Всі поля заповнені поточними значеннями
- [ ] Редагування будь-якого поля:
  - [ ] Зміни зберігаються при клісі "Зберегти"
  - [ ] Помилка: повідомлення на екрані
  - [ ] Успіх: список оновлюється
- [ ] Скасування без збереження: закриває форму без змін
- [ ] Запит на підтвердження при удаленні

## Видалення спеціаліста
- [ ] Кнопка "Видалити" видимо
- [ ] Модальне вікно з підтвердженням: "Ви впевнені?"
- [ ] "Так" → запис видаляється з бази, списку, UI
- [ ] "Ні" → модаль закривається, запис залишається
- [ ] Після видалення: зникає зі списку незразу (без перезагрузки)

## Валідація та помилки
- [ ] Сервер недоступний: показується повідомлення "Помилка синхронізації"
- [ ] Інтернет відключився: локальні зміни зберігаються, синхро поновлюється
- [ ] Дублікат (та сам спеціаліст редагується): коректна обробка
- [ ] Невірні дані: полі підсвічується червоним, текст помилки показується
- [ ] Сервер 500: показується "Помилка сервера, спробуйте пізніше"

## Перформанс
- [ ] Навантаження 100+ записів: таблиця не зависає
- [ ] Редагування в режимі реального часу: без затримки
- [ ] Сортування > 500 записів: < 1 сек

## Синхронізація з Google Sheets (якщо інтегровано)
- [ ] Дані синхронізуються з Google Sheets
- [ ]새 запис у адмінці → з'являється в Sheets (в межах 1-2 хвилини)
- [ ] Видалення в адмінці → видаляється з Sheets
- [ ] Редагування: обидві сторони синхронізуються

## Доступність
- [ ] Форми працюють з клавіатурою (Tab, Enter)
- [ ] Лабели пов'язані з полями (for="id")
- [ ] Текст помилок контрастний
- [ ] Модальні вікна закриваються по Escape
- [ ] Екранні читачі читають форми коректно

## Безпека
- [ ] Пароль не показується під час введення (кружечки)
- [ ] Сеанс завершується при неактивності (30-60 хв)
- [ ] На чужому комп'ютері: "Запам'ятати мене" не вмикається
- [ ] XSS: в полях для введення не виконуються скрипти
- [ ] SQL injection: спеціальні символи обробляються безпечно

## Email Notifications (Нові вимоги)

### Вимога 1: ID спеціаліста як лінка
- [ ] При нотифікації про нову заявку, ID спеціаліста має бути **лінкою на редагування** в адмінці
- [ ] Лінка має вести на правильну картку в живому каталозі
- [ ] Формат: `ment-thousands-chemicals-windsor.trycloudflare.com/admin.html?id=<spec-id>`

### Вимога 2: Звіт про неточність в адмінці
- [ ] В адмінці має бути кнопка "Звіт про неточність" при редагуванні картки
- [ ] При натисканні — відкривається форма для логування неточності
- [ ] Неточність записується як окрема заявка типу "Звіт про неточність"

### Вимога 3: Email лінки в тексті
- [ ] Посилання на адмінку вставляються **в текст** повідомлення (не голі)
- [ ] Посилання мають текст-якір типу: "Редагувати картку в адмінці"
- [ ] HTML email формат з гарним стилем
